# 知识学习与能力提升计划

学习计划的目的不是“学完一门课”，而是**让某条 JD 要求从“暂无证据”变成“已证明”**，并且面试时讲得出来。

## 1. 先分缺口类型

| 缺口类型 | 典型表现 | 对应动作 |
|---|---|---|
| 表达缺口 | 做过，但说不清方法和贡献 | 整理过程，重写经历，练习讲述（不需要学新知识） |
| 证据缺口 | 声称掌握，但没有作品或记录 | 找回真实材料，或补做一个可验证的小练习 |
| 技能缺口 | 尚不能完成岗位关键任务 | 学习必要知识 + 实际完成任务并复盘 |
| 条件不符 | 明确资格或到岗条件无法满足 | 核实是否可协商，调整投递策略 |

优先处理：与核心职责直接相关 × 在剩余时间内能产生实际改善。短期准备可以补表达和部分实操，不能承诺几天内替代长期经验——要明确说出哪些属于长期能力。

## 2. 知识地图（每个技能缺口一张）

| 知识点 | 对应 JD 原文 | 需掌握程度 | 面试常见考法 | 优先级 | 预计用时 |
|---|---|---|---|---|---|

- **需掌握程度**用三档：能说清概念 / 能独立完成常规任务 / 能排查问题并比较方案。参照 JD 的“了解/熟悉/掌握/精通”定档。
- **面试常见考法**：概念解释、手写/实操、结合项目追问、情景题。
- 知识点要具体到可以检验，例如不写“学 SQL”，而写“多表 JOIN、GROUP BY + 聚合、窗口函数（排名/累计）、常见指标（留存、转化率）的查询写法”。

## 3. 练习任务（每个学习模块配一个）

> 岗位要求 → 当前缺口 → 练习任务 → 预计用时 → 交付物 → 验收标准 → 完成后可如实写进简历的表述

示例（按真实岗位替换）：

| 能力方向 | 练习任务 | 交付物 | 验收标准 |
|---|---|---|---|
| 内容运营 | 为指定人群设计一组选题并完成样稿 | 选题说明、样稿、复盘 | 能解释人群、目标和内容选择 |
| 数据分析 | 用公开数据回答一个业务问题 | 分析文件、图表、结论 | 能复现计算并说明局限 |
| 产品 | 拆解一个使用问题并提出可验证方案 | 需求说明、流程图或原型 | 能解释问题证据、取舍和验证方法 |
| 设计 | 按明确需求完成一个设计任务 | 设计稿、过程说明 | 能解释信息层级与设计决策 |
| 开发 | 实现一个带错误处理的小功能并部署 | 代码仓库、README、运行截图 | 他人能按 README 跑起来；能讲清关键实现 |
| 测试 | 为一个开源/自建应用写测试用例并提缺陷 | 用例表、缺陷记录 | 覆盖正常/异常/边界；缺陷可复现 |

完成后才写进简历，标注“个人项目 / 课程项目 / 练习项目”；分析中的预期收益不能写成已实现业绩。

## 4. 学习资源建议的写法

给**资源类型 + 检索关键词 + 用法**，例如：“官方文档的 Quick Start 和教程章节（检索：『××官方文档 入门』），只看与练习任务相关的部分”“Kaggle/天池等平台上的公开数据集（检索：『电商用户行为 数据集』）”。
不确定是否存在的具体课程名、书名版本、链接不要编造；经典且确定存在的教材/官方文档可以点名。

## 5. 排期规则

- 根据剩余天数 × 每天时长计算总预算，先分配给：简历事实核对与重写 → 核心技能缺口的最小练习 → 面试讲述练习 → 次要缺口。
- 每天的安排都要有当日交付物；学习与练习交替，不要连续几天只“看课”。
- 留出至少一次模拟面试和复盘时间。
- 时间极短（1–2 天）时，不安排新技能学习，只做：核实简历事实、练熟自我介绍和重点项目、准备 JD 核心知识点的概念级回答。
- 时间较长（2 周以上）时，扩大练习规模并增加反馈轮次，可按周规划。

## 6. 默认 7 天框架（每天约 2 小时）

| 天 | 任务 | 当日交付 |
|---|---|---|
| 1 | 拆 JD、盘点经历与缺口 | 岗位要求清单、证据匹配表 |
| 2 | 简历定位、结构与文案 | 定制简历初稿、待确认清单、打招呼话术 |
| 3 | 核对事实，整理重点经历；开始核心知识点学习 | 简历修订稿、项目讲述提纲 |
| 4 | 针对一个关键缺口做最小练习 | 可检查的练习产出 |
| 5 | 完善练习，准备自我介绍与岗位题 | 作品说明、回答提纲 |
| 6 | 模拟面试并复盘 | 薄弱项记录、针对性修改 |
| 7 | 检查材料与面试安排 | 最终简历、面试速查页、反问清单 |
