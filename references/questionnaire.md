# 信息收集问卷：出题规则与 JSON 格式

问卷的目的：用最少的打字量，拿到“证据匹配表”需要的事实。用户觉得逐条打字回答很枯燥，所以**能点选的就不要让人打字**。

## 一、出题规则

1. **题目从证据匹配表来**：每道题对应一条或几条 JD 要求中“待确认 / 暂无证据”的项；`why` 写清对应 JD 哪句（例如“对应 JD：熟练使用 Cursor、Claude Code 等 AI 编程工具”）。
2. **数量**：8–14 题，分 3–5 组。必含：
   - 基本信息（学校/专业/年级或毕业年份）——`text`
   - 硬条件能否满足（到岗天数、实习时长、城市、最早到岗时间）——`single` + `detail`
   - 准备时间（几天后投递、每天几小时）——两道 `single`
   - 原简历粘贴入口——`textarea`，`optional: true`，提示“粘贴后其他题可以少填”
   - **简历基础信息**（放在问卷最后一组，标题“简历基础信息”；用户已贴简历就只问简历里缺的）：
     - 姓名、手机、邮箱：`text`，`optional: true`，`quick: ["最后自己填"]`。提示信息只保存在本地；选“最后自己填”时，简历里保留【占位符】。
     - 教育起止时间与 GPA 或排名：`text`，placeholder 例如“2024.09–2028.06，GPA 3.6/4.0，专业前 10%（没有就不写）”。
     - 相关课程：`text`，`optional: true`。
     - 重点经历的起止时间：`textarea`，placeholder 为“每行一个：项目或经历名 / 起止年月”。
     - 简历要不要放照片：`single`，选项为“不放（互联网/技术岗通常不放）”“放”“不确定”。
3. **优先选择题**：把“程度”“有没有”“用过哪些”做成 `single` / `multi`，选项要**贴合这个 JD**（工具名、技术栈、场景都用 JD 里的词），并给出“没有 / 不确定”这类兜底选项。选项写成可直接判断能力等级的描述，例如“能独立写小功能或小网页”，而不是“熟练 / 一般”。
4. **需要事实细节的地方**（项目做了什么、个人分工、数据）：用 `detail` 字段在选择题下加选填补充框，或用 `textarea` 并在 `placeholder` 里给出填写示例（“例：用 Python 分析了 Kaggle 电商数据，我负责清洗和可视化”）。
5. **不问已知信息**：用户已在对话中说过的（专业、年级、已有简历）不再问；用户已给完整简历时，只问简历里看不出来的部分（分工、数据口径、到岗条件、时间）。
6. 题目措辞口语化、友好；避免一次问多个问题。

## 二、JSON 格式

```json
{
  "id": "acme-ai-pm-intern",
  "title": "某科技公司 · AI产品实习生",
  "subtitle": "深圳·5天/周·3个月｜400-450元/天",
  "jd_url": "https://…",
  "file_name": "求职问卷回答_acme-ai-pm-intern",
  "intro": "（可选）页面顶部说明，默认会提示复制或下载",
  "sections": [
    {
      "title": "基本情况",
      "questions": [
        {
          "id": "school",
          "type": "text",
          "label": "学校 / 专业 / 年级（或毕业年份）",
          "placeholder": "例：XX大学 / 工业设计 / 大三",
          "why": "对应 JD：本科及以上，在读或应届"
        },
        {
          "id": "onsite",
          "type": "single",
          "label": "能否每周 5 天到深圳办公、连续 3 个月？",
          "options": ["可以", "可以但需要调课", "只能每周 3–4 天", "不确定"],
          "detail": "最早到岗日期 / 其他说明（选填）",
          "why": "对应 JD：5天/周·3个月"
        },
        {
          "id": "tools",
          "type": "multi",
          "label": "用过哪些 AI 编程工具？",
          "options": ["Claude Code", "Cursor", "Codex", "GitHub Copilot", "都没用过"],
          "allow_other": true
        },
        {
          "id": "resume",
          "type": "textarea",
          "label": "已有简历可以直接粘贴在这里",
          "optional": true,
          "rows": 6,
          "quick": ["暂时没有简历"]
        }
      ]
    }
  ]
}
```

字段说明：
- `type`：`single` 单选、`multi` 多选、`text` 单行、`textarea` 多行。
- `options`：选择题必填；`allow_other: true` 时自动追加“其他”并出现输入框。
- `detail`：`true` 或一段提示文字，在选择题下加一个选填补充框。
- `quick`：文本题下的一键填入按钮（如“没有”“不确定”）。
- `optional`：选填题；`hint`：题目下方的灰色说明；`placeholder`：输入框示例；`rows`：多行框高度。
- `file_name`：下载文件名（不含扩展名），建议 `求职问卷回答_<id>`，方便之后在「下载」文件夹里找到。

## 三、生成与打开

```bash
# 推荐：后台运行，启动本地服务（127.0.0.1）并自动打开浏览器
python3 <skill目录>/scripts/make_form.py <工作目录>/问卷_<id>.json <工作目录>/问卷_<id>.html --serve
```

脚本会先校验 JSON（缺 id、重复 id、选择题缺选项等都会报错），再填入模板生成页面。页面是卡片引导式的：
- 开头一张欢迎卡，然后一屏一题，最后一张检查页，点任意一条可以回去修改。
- 单选题选完自动进入下一题（有补充框的题除外）；数字键 1–9 选择，Enter 下一题，← 上一题。
- **语音输入**：文本框和补充框都有麦克风按钮。选择题可以直接说出答案，页面会自动匹配选项（也支持“第三个”这类说法），对不上选项的内容会放进补充框或“其他”。
  - 使用浏览器的 Web Speech API，Chrome 和 Edge 支持最好，需要联网，页面要在 localhost 下打开。
  - 浏览器不支持时，页面会提示改用系统听写（Mac 按两下 Fn）。
- 填写内容自动保存在浏览器本地，关掉页面再打开不会丢。

其他参数：
- `--open`：用本地文件方式打开，不启动服务；语音可能用不了，也没有“提交”按钮。
- `--no-open`：只启动服务，不打开浏览器。
- `--port`：默认 8765，被占用时自动顺延。
- `--timeout`：服务默认 3 小时后自动退出。

## 四、读取回答

用户有三种交回方式：
1. **提交（`--serve` 模式，推荐）**：回答保存在问卷 HTML 同目录下的 `<file_name>.md`。用户说“填好了”时先读这个文件。
2. **粘贴**：文本以 `【求职问卷回答｜boss-job-plan】` 开头。
3. **下载**：到 `~/Downloads/` 查找最新的 `求职问卷回答_<id>*.md`（浏览器可能加 `(1)` 之类后缀，取修改时间最新的）。

都找不到就请用户粘贴。拿到回答后结束后台服务进程。

“（未回答）”“不确定”的项保留为“待确认”，不要自行补全；回答里出现新的经历细节，追问时只问真正影响简历表述的部分。

## 五、第二轮追问

第一轮回答后，如果仍有影响简历表述的关键事实缺失（项目个人角色、上线状态、链接、获奖作品与时间、数据口径、勾选了但没写细节的经历），**先根据已有回答更新方案，再生成第二轮问卷**（`id` 加 `-2` 后缀），只问这些细节：
- 角色、状态这类信息继续用单选，例如“独立完成 / 团队负责人 / 团队成员”“已上线有用户 / 可演示 Demo / 本地运行 / 原型”。
- 多个同类条目（例如多个奖项）合并成一道 `textarea`，在 placeholder 里给出“每行一个：字段 / 字段 / …”的格式示例。
- 用一道单选让用户决定选做任务做不做，日程据此调整。
- 第一轮里含义模糊的回答（例如“2028 级”既可能指入学年份，也可能指毕业年份）单独列一题确认，不要自行假设。
