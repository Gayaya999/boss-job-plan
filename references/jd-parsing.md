# BOSS直聘 JD 拆解指南

## 一、BOSS 岗位页的典型字段

| 字段 | 位置 | 拆解时怎么用 |
|---|---|---|
| 职位名称 + 薪资区间（如 8-12K·13薪 / 150-200元/天） | 顶部 | 判断层级；“·13薪”“元/天”说明薪资结构与是否为实习 |
| 城市 / 区域、经验要求、学历要求 | 顶部标签 | 明确条件；“经验不限”“在校/应届”是校招/实习信号 |
| 实习要求（如“4天/周”“实习3个月”） | 实习岗标签 | 硬条件，打招呼话术里要正面回应 |
| 职位标签（技能关键词） | 职位描述上方 | 往往是 HR 筛选关键词，简历中真实具备的要用相同措辞 |
| 职位描述：岗位职责 / 任职要求 / 加分项 | 正文 | 四类信息的主要来源 |
| 公司信息：行业、规模、融资阶段、工作地址 | 侧栏/底部 | 判断业务形态与面试可能关注点；地址判断通勤 |
| 招聘者身份（HR / 部门负责人 / 猎头）、活跃度 | 招聘者卡片 | 部门负责人发布 → 面试偏业务；猎头 → 可能非直招；“刚刚活跃”回复概率高 |
| 福利标签 | 页面 | 只作参考，具体以 offer 为准 |

截图或粘贴文本可能缺字段，缺了就在方案里写“页面未提供：××”，不要脑补。

## 二、四类信息提取

1. **明确条件**：学历、专业限制、经验年限、证书、城市、到岗时间、实习时长、语言要求。
2. **主要任务**：每条“负责/参与/协助……”拆成“动作 + 对象 + 交付物”。动词透露层级：“协助/支持”偏执行，“负责/主导/搭建”要求独立承担。
3. **关键能力**：把任职要求里的“熟悉/掌握/了解/精通”逐条拆出，并对应到具体任务。程度词的大致含义：了解 < 熟悉 < 掌握/熟练 < 精通。
4. **加分项与待核实项**：“优先”“加分”“有……经验者更佳”列为加分；职责中模糊或页面没写的列为待核实。

## 三、常见表述与需要核实的“暗示”

以下是需要提醒用户核实的线索，**不是定论**：

| JD 表述 | 可能意味着 | 建议核实 |
|---|---|---|
| 抗压能力强、适应快节奏 | 工作强度较大或目标压力 | 加班情况、考核方式 |
| 有目标感、结果导向、业绩 | 可能有业绩/销售指标 | 是否有 KPI、提成与底薪结构 |
| 管培生、储备干部 | 招聘项目名，不等于具体职责 | 轮岗内容、定岗方向、工作地点 |
| 接受出差/驻场/外派/区域调配 | 工作地点不固定 | 频率、时长、补贴 |
| 综合薪资、薪资面议 | 薪资构成不透明 | 底薪、绩效、试用期比例 |
| 客户经理、顾问、BD | 常含销售或拓客 | 服务对象、考核方式 |
| 一人多岗式长列表职责 | 小团队或职责边界不清 | 团队规模、汇报对象 |
| 技术服务、解决方案 | 仍可能需要专业深度，且常出差 | 技术深度要求、出差比例 |

## 四、关键能力排序规则

- **核心**：出现在岗位职责中，且在任职要求或职位标签里再次出现。
- **重要**：只出现在任职要求中，或职责中提到但未展开。
- **加分**：只在“优先/加分”中出现。

如果用户提供了多个同方向 JD，可以合并统计反复出现的要求——但说明这只是小样本，不代表整个市场。

## 五、信息不足时

- JD 只有两三行：基于职位名称和行业做“常见职责推断”，**明确标注为推断**，并建议用户在 BOSS 上搜索 3–5 个同名岗位做对比，或在打招呼时询问具体工作内容。
- 链接打不开：请用户粘贴文字或截图；保留链接与读取日期。
- 截图不完整：列出缺失部分。

## 六、硬条件不符时的处理

区分“明确不符”（如要求硕士、只招 2026 届）与“可协商”（如“1 年以上经验”对优秀应届生有时可放宽）。前者建议调整目标或换同类岗位；后者在打招呼话术中用事实正面说明，不回避也不夸大。
