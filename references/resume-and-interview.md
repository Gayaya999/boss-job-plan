## 1. 素材盘点

每段经历至少确认：时间、组织/项目名称、经历性质（实习/课程/竞赛/社团/个人项目）；任务是什么、自己负责哪部分；实际动作与方法；产出与有记录可查的结果；团队成果与个人贡献的边界。

缺失项写成具体问题，例如：“你在这个项目里写的是哪几个模块？”“这份报告最后给谁用了？有没有反馈？”“粉丝增长数是后台截图还是估算？”

## 2. 简历结构与取舍

- 默认顺序：基本信息 → 教育背景 → 相关经历（实习/工作）→ 项目 → 校园经历（与岗位相关时）→ 技能与证书。
- 应届生/实习：相关项目可前置；社招：相关工作经历和成果前置。
- 校招简历通常 1 页，信息量大时社招可 2 页；以投递要求为准。
- 每段材料给出结论：**重点展开 / 保留压缩 / 暂不使用 / 待补证据**，并写出依据（对应哪条 JD 要求、事实强度如何）。
- 技能栏写“用它完成过什么”，并用与 JD 一致的关键词；“了解/熟悉/熟练”如实分级。
- 照片、证书、政治面貌等栏目按岗位和行业习惯决定，不套统一模板。

## 3. 经历文案写法

骨架：为解决【具体问题】，负责【个人任务】，通过【方法/动作】，形成【交付物】，取得【可核实结果】。
不必每句塞满所有要素；缺结果数字时，写交付物、完成范围或方法，并加入待确认清单。

动词与真实角色匹配：主导/负责（独立承担并对结果负责）> 参与/协助（承担其中一部分）。不能随意升级。

**改写示例（示意，非任何用户的真实经历）：**

- 原始：“参与社团活动宣传。”
- 追问后若属实：“负责【活动名称】线上宣传，撰写【N】篇推文并按【排期】在公众号发布；据后台数据，活动报名【N】人（较上届【变化】）。”
- 原始：“做了一个课程项目，用 Python 分析数据。”
- 追问后若属实：“课程项目｜基于【公开数据集】分析【业务问题】，独立完成数据清洗（处理缺失值与异常值）、【方法】建模与可视化，输出【N】页分析报告，结论被用于课程答辩。”

## 4. 简历方案六项输出

1. 目标岗位定位与优先展示的能力（1–3 个，对应核心要求）。
2. 栏目顺序、篇幅与版式安排。
3. 经历取舍表（经历 / 结论 / 对应 JD 依据）。
4. **按最终栏目顺序排列、可直接复制的完整文案草稿**。
5. 版式建议：中文常用思源黑体/微软雅黑，正文约 10–11 号，标题层级不超过 3 级，页边距一致；导出 PDF；命名“姓名-岗位-学校/年限-电话.pdf”或按 JD 要求。
6. 待确认事实、数字、日期与占位符清单。

## 5. BOSS 打招呼话术

BOSS 上 HR 每天收到大量消息，回复率取决于前一两句是否让对方看到“匹配”。原则：短、具体、对上核心要求、包含 HR 需要的筛选信息。

**结构**：问候 + 应聘岗位 → 1–2 个与核心要求对应的真实亮点（最好带具体事实）→ 关键条件（到岗时间、实习时长/每周天数、城市）→ 请求查看简历。

**模板（占位符需替换为真实信息）：**

- 简洁版：您好，我是【学校】【专业】【届别】的【姓名】，想应聘【岗位】。我做过【与核心要求对应的事+结果】，可【到岗时间/每周N天，实习N个月】。附件是我的简历，期待您查看～
- 突出经历版：您好！看到岗位需要【JD 核心要求原文关键词】，我在【经历】中负责【任务】，【方法】完成了【可核实结果】。人在【城市】，【可到岗时间】，方便的话想发简历给您看看。
- 差距说明版（如经验年限略不足）：您好，我是【背景】，虽然【差距的如实说明】，但在【经历】中已经做过【与职责对应的任务】，【结果】。非常希望有机会沟通，简历已附上。

**常见 HR 追问的回复思路**：能实习多久/每周几天（直接给确定数字）；期望薪资（给区间并表示可按岗位标准沟通，区间参考 JD 标注范围）；何时到岗（给具体日期）；为什么想来（一句岗位理由 + 一句个人匹配）。

避免：只发“您好”；复制同一段话给所有岗位；夸大或与简历不一致。

## 6. 自我介绍

结构：相关背景 → 核心能力 + 事例 → 求职动机。只讲与本岗位最相关的 1–2 段经历，不复述整份简历。

> 面试官您好，我是【姓名】，【学校/专业/届别或工作年限】。和这个岗位最相关的经历是【经历】，当时我负责【任务】，通过【方法】完成了【结果】，这让我在【JD 关键能力】上有了实际积累。此外【第二个能力 + 一句证据】。我选择这个岗位，是因为【基于事实的动机：对业务/职能的了解】，希望在【方向】继续深入。

输出 30 秒版（打电话/群面）和 1–2 分钟版（正式面试）。涉及对公司现状的判断提醒用户自行核实。

## 7. 重点经历讲述

对简历中每段重点经历准备六问：
1. 当时要解决什么问题，为什么值得做？
2. 你具体负责什么，团队如何分工？
3. 为什么选这个方法，考虑过其他方案吗？
4. 遇到什么困难，怎么处理？
5. 结果如何记录，数字怎么算出来的？
6. 有哪些限制或失败，重做会怎么改？

用 STAR（情境—任务—行动—结果）给每段写回答提纲，行动部分占一半以上篇幅。素材不足的地方写成待补问题，不替用户编故事。

## 8. 岗位问题清单

每类 2–4 题，每题给：**考察点 → 回答思路 → 可用素材（来自用户真实经历）→ 避坑点**。所有题目标注“基于 JD 推演”。

| 类型 | 生成依据 |
|---|---|
| 岗位理解与动机 | 职责描述、公司业务 |
| 专业与工具能力 | 关键能力中的知识点和工具（与学习计划的知识地图对应） |
| 项目追问 | 简历重点经历 |
| 业务情景题 | 主要任务中的典型场景（例：“新品上线一周转化低于预期，你会怎么排查？”） |
| 协作与分歧 | 职责中涉及的跨部门协作 |
| 薄弱项说明 | 证据匹配表中的“暂无证据/部分证明”项 |

## 9. 薄弱项与敏感问题

结构：**事实说明 → 可迁移能力 → 已做/正在做的补足行动**。

- 跨专业：说明为什么选这个职能、了解到的真实工作、已完成的试做任务。
- 没有实习：用课程/个人项目说明做事方法，强调已完成的练习产出。
- 硬条件差距：坦诚说明，不找借口，突出能弥补的部分。
- 空窗期：简短如实说明这段时间做了什么。
- 离职原因（社招）：聚焦发展诉求，不贬低前东家。

## 10. 模拟面试与反问

模拟：一次问一题，根据回答追问。反馈四点：是否答到问题、是否有事实支撑、是否讲清个人贡献、表达是否清楚；并给出下一次要修改的那一句或要补的材料。

反问（选 2–3 个）：
- 这个岗位入职后前三个月最重要的工作是什么？
- 团队目前规模和分工是怎样的？这个岗位和哪些角色配合最多？
- 这个岗位的考核看哪些方面？
- 对新人有怎样的培养方式？
- （待核实项）例如：是否需要出差/驻场？薪资中绩效部分如何计算？——薪资细节更适合在 HR 面或 offer 阶段询问。
